# mediatidy-rule

> MediaTidy 自用规则集：分类（37 条，扁平两级结构）、命名（点号分隔 + 中英双标题）、质量评分（电影多版本 1 ISO + 1 非 ISO / 剧集单版本）。

规则按实际媒体库整理场景调过，目标是：目录结构不乱、命名可读、洗版判断贴近实际观感。

> MediaTidy 的三种规则语法**互不通用**，请勿混用。详见下方「三套语法的区别」。

## 文件清单

| 文件 | 类型 | 规则条数 | 作用 |
|---|---|---|---|
| `mediatidy-category.yaml` | 分类规则 | 37 条（电影 18 / 剧集 19） | 按 TMDB 元数据把媒体归到对应目录 |
| `mediatidy-naming.yaml` | 命名规则 | 2 条（1 条启用 / 1 条注释保留） | 生成目录名与文件名 |
| `mediatidy-quality.yaml` | 质量评分规则 | 1 条（同时管电影/剧集） | 候选资源打分，决定留哪个版本 |

三个文件都做了详尽的中文注释，可以直接改，不需要另查文档。

## 一、分类规则 `mediatidy-category.yaml`

按 TMDB 元数据（类型、语言、国家、关键词、演员导演、分级）把文件分到对应目录。**顶层只有 `movie` 和 `tv` 两个区块，键就是目标相对路径，从上到下匹配，命中第一条即停。**

### 目录结构（扁平两级）

分类目录只到二级，不放三级系列目录 —— 实测完整的库只有 2 级（`影视库/电影/华语电影`），
所以规则也按这个结构写，不会额外创建目录。

```
电影（8）    华语 / 日本 / 韩国 / 东南亚 / 印度 / 欧美 / 其他地区 / 动画电影
剧集（6）    国产 / 港台 / 日本 / 韩国 / 欧美 / 其他地区
动漫（3）    国漫 / 日番 / 欧美漫           ← 只放剧集，动画长片统一进 电影/动画电影
R级（5）     华语电影 / 亚洲电影 / 欧美电影 / 剧集 / 动画电影
特摄剧（2）  电影 / 剧集
综艺（2）    电影 / 剧集
儿童（2）    动画片 / 剧集
纪录片（2）  电影 / 剧集
演唱会（3）  华语 / 日韩 / 欧美歌手演唱会
_未整理/剧集ISO
```

### 匹配优先级

```
电影：特摄剧电影 → 综艺电影 → 演唱会 → 纪录片 → R级（动画→华语→亚洲→欧美）
     → 电影/动画电影 → 电影（华语/日本/韩国/东南亚/印度/其他地区/欧美兜底）
剧集：剧集ISO拦截 → 特摄剧剧集 → 综艺剧集 → 演唱会 → 纪录片 → R级剧集
     → 儿童 → 动漫 → 剧集（国产/港台/日本/韩国/欧美/其他地区兜底）
```

原则是**题材优先，国家兜底**：先判断「这是什么类型的片」，再判断「这是哪国的片」。

**演唱会为什么排在纪录片之前**：演唱会规则要求「音乐类型 + 标题含演唱会类词」两个条件，已经很窄；
而带 `99` 标签的演唱会实况（如 The Eras Tour）必须先被它接住，否则会被纪录片规则抢走。
纯音乐纪录片标题不含这类词，会自然落到纪录片。

### 关键设计

- **R级用标签关键词判定**（`include_keywords` 命中 `eroticism`、`softcore`、`hentai` 等），不用 `content_ratings`。国产片在 TMDB 上基本没有分级数据，靠分级判断会永远落空。
- **R级动画单独收口**到 `R级/R级动画电影`，且整段 R级 排在 动漫/儿童 之前，避免情色动画被 国漫/日番/儿童 吃掉。
- **儿童排在动漫之前**：儿童动画靠「`+16,+10762` 双类型」或「系列名关键词」命中；国漫/日番只按 `genre_ids: "16"` 判类型。
  顺序上儿童在前，所以儿童动画不会漏到动漫里。
- **动画长片统一进 `电影/动画电影`**，不再按国别细分；`动漫` 只收剧集（国漫/日番/欧美漫）。
- **剧集 ISO 不入库**：`tv` 段第一条规则把 `file_extension: "iso"` 的文件收进 `_未整理/剧集ISO`，
  避免它被质量评分当成独立版本保留。电影的 `.iso` 不受影响，仍进电影目录。
  （分类规则没有「跳过」动作，只能改道；要文件完全不动请用面板里的「媒体封板」。）
- **兜底**：电影靠 `电影/欧美电影`（无条件），剧集靠 `剧集/其他地区`（无条件）。
  注意剧集侧 `欧美剧集` 是明确的国家/语言列表，不是兜底 —— 泰、印、土、俄、非洲等未命中的都归 `其他地区`。
  电影侧 `电影/其他地区电影` 是明确列表，兜底仍在 `欧美电影`。
- 华语范围统一含 `MO`（澳门）。

### 条件语法速查

| 写法 | 含义 |
|---|---|
| `"16,99"` | 逗号 = OR |
| `"-zh"` | 值前缀 `-` = 排除，命中则整条规则失败 |
| `"+16,+10762"` | 值前缀 `+` = 必须同时具备（**仅 `genre_ids`**） |
| `?字段名: "x"` | 字段前缀 `?` = 可选条件，多个可选之间 OR |
| `-字段名: "x"` | 字段前缀 `-`/`!` = 整个条件取反 |
| 无条件 | 保底规则，永远命中 |

匹配公式：**所有必须条件 AND 通过，且（无可选条件 或 至少一个可选条件通过）**。

## 二、命名规则 `mediatidy-naming.yaml`

### 目录格式（Emby / Jellyfin 方括号写法）

```
电影：暗杀风暴 (2023) [tmdbid-902533]
剧集：八零九零 (2021) [tmdbid-116184]/Season 01
```

方括号 `[tmdbid-xxx]` 是 Emby/Jellyfin 的认库语法；Plex 用的是单花括号 `{tmdb-xxx}`，两者不要混用。

### 文件名格式

**中文标题.英文标题.年份.季集.属性.属性.扩展名**，所有属性之间一律用点号，不用空格或横杠：

```
案发现场.Scene of Crime.2004.S01E01.2160p.AAC.AVC.mp4
流浪地球.The Wandering Earth.2019.2160p.DTS-HD MA.HEVC.HDR10.10bit.7.1.Atmos.BluRay Remux.FRDS.mkv
```

属性顺序：分辨率 → 音频编码 → 视频编码 → HDR → 色深 → 声道 → 音频特性 → 片源 → 流媒体 → 版本 → 压制组。

### 两条规则

| 规则 | 状态 | 差异 |
|---|---|---|
| `full-info` | 已注释，保留备用 | 文件名不带字幕信息 |
| `full-info-sub` | **启用** | 末尾多一段 `{{probeSubtitle}}` 字幕轨摘要 |

`full-info-sub` 需要开启 ffprobe 元数据提取才有效，否则字幕段为空（输出退化成 `full-info`）。

### 已知副作用

- TMDB 没有中文标题时 `{{title}}` 会回退成原名，可能出现 `Scene of Crime.Scene of Crime.2004...` 的重复。命名规则没有条件分支，无法去重。
- 标题内部原有的空格会保留（`Scene of Crime` 就是这样），这里只约束**属性之间**的分隔符。

## 三、质量评分规则 `mediatidy-quality.yaml`

给每个片源算一个总分，分数高者优先入库；开启「洗版升级」后，新资源要比现有文件**高出 `min_score_diff` 分**才会替换。

### 评分公式

```
总分 = Σ（weight × 该项位置分）
```

位置分：`priority` 有 N 项时，第 1 项 10 分，第 2 项 `10×(N-1)/N` 分……最后一项 `10/N` 分，未命中 0 分。

所以**一个维度的最高影响力 = weight × 10**，总分满量程 1000 分。

> 位置分是固定等差数列，**无法自定义某两档之间的间距**，也**没有负分**。要拉大差距只能调整 `weight`，或减少 `priority` 的档位数（档位越少间距越大）。

### 权重表（总和 100）

**前三项主导，合计占 75%：**

| 维度 | 权重 | 满分贡献 |
|---|---|---|
| 分辨率 `resolution` | 34 | 340 |
| HDR `hdr` | 25 | 250 |
| 片源 `source` | 18 | 180 |

**其余七项占 23%：**

| 维度 | 权重 | 满分贡献 |
|---|---|---|
| 音轨 `audio_codec` | 11 | 110 |
| 视频编码 `video_codec` | 6 | 60 |
| 色深 `color_depth` | 2 | 20 |
| 文件大小 `file_size` | 1.5 | 15 |
| 帧率 `frame_rate` | 1 | 10 |
| 容器 `file_extension` | 1 | 10 |
| 字幕 `subtitle` | 0.5 | 5 |
| 总码率 `bitrate` | 关闭（预设 6） | — |

配平思路：分辨率 34% 最高、HDR 25% 次之、片源 18% 第三（原盘/蓝光/网络源决定画质天花板）；音轨 11%、视频编码 6% 只作辅助；字幕只有 5 分。

直接后果：**1080p 的 Remux/蓝光有机会赢 2160p 的 WEB-DL**（片源差最多 112.5 分，分辨率差 85 分）。

### 为什么只有一条规则

MediaTidy 的「洗版升级」在整理方案里只能绑定**一个**评分规则（`qualityRuleId`），电影和剧集无法各用一条。所以这里用一条规则同时满足两种需求：

- `.iso` 文件进「ISO 原盘」槽，组内留最优 1 个
- 其余格式进「未匹配组」，组内留最优 1 个
- **电影**：ISO 有值 + 常规有值 → 两版并存
- **剧集**：`.iso` 已被分类规则拦到 `_未整理/剧集ISO`，ISO 槽为空 → 单版本

换句话说，对剧集是「自然退化成单版本」，不需要额外开关。

```yaml
version:
  enabled: true
  unmatched: best
  slots:
    - name: ISO 原盘
      match:
        file_extension: [iso]
```

实测：电影 2 个 ISO + 3 个非 ISO → 留下 2 个（ISO 组 859.1 分 + 常规组 626.4 分）；剧集 4 个候选 → 留下 1 个（650.1 分）。

> 如果你的版本支持「按分类目录选择评分规则」，也可以拆成电影、剧集两条，分别调 `min_score_diff`。目前两条的权重完全相同，只有版本槽不同，所以合并没有任何损失。

### 洗版门槛的实际效果

以现有文件「1080p 蓝光 H.264 8bit DTS-HD MA 5.1 12GB（407.0 分）」为例：

| 新来的候选 | 分差 | 判定 |
|---|---|---|
| 同 1080p，只换片源成 Remux+蓝光 | +67.5 | 保留旧版 |
| 同 1080p，只换编码 H.264→H.265 | +20.0 | 保留旧版 |
| 同 1080p，只换色深 8bit→10bit | +6.7 | 保留旧版 |
| 同 1080p，换片源 + 音轨升 7.1 | +91.9 | 洗版 |
| 升 4K 但片源音轨降级（WEB-DL DDP） | +76.9 | 保留旧版 |
| 升 4K 蓝光 HDR10 | +195.0 | 洗版 |
| 升 4K 杜比视界原盘 | +461.1 | 洗版 |

阈值 80 是算出来的：卡在「片源微调 +67.5」和「分辨率跃升 +85 / HDR 跃升 +83」之间，两侧留 12 分余量。所以**只有档位跃升才洗版**；单纯换片源、换编码、换色深都不动。想更保守调到 100，想更敏感降到 50（那样换片源就会开始洗版）。

### 排除规则

```yaml
exclude:
  resolutions: [576p, 480p, 360p]
  codecs: []
  hdr_types: []
```

命中任一项直接跳过、不参与评分。注意 `exclude` 是**精确匹配**，不像 `priority` 支持前缀匹配 —— 排除 `HDR10` 不会连带排除 `HDR10+`。另外 `exclude` 只支持分辨率、视频编码、HDR 三项，**不支持文件后缀**。

## 三套语法的区别

这是最容易踩的坑：三份配置长得像 YAML，但语法完全不是一回事。

| | 分类规则 | 命名规则 | 质量评分规则 |
|---|---|---|---|
| 顶层键 | `movie` / `tv` | `naming`（列表） | `quality`（列表） |
| 核心内容 | 目录路径 : 匹配条件 | `folder` / `file` 模板 | `enabled` / `weight` / `priority` |
| 条件语法 | `?` `-` `+` 逗号 OR | **没有** | **没有** |
| 模板变量 | **没有** | `{{title}}` `{{year}}` 等 | **没有** |
| 逻辑 | 顺序匹配，命中即停 | 纯文本替换 | 加权求和 |
| 合并方式 | **整体替换**（本地有就用本地） | 按 `name` 合并（同名覆盖） | 按 `name` 合并 |

## 使用方法

1. 在 MediaTidy「规则引擎」里，把对应文件的 YAML 内容粘贴/导入到分类、命名、质量评分三个编辑区。
2. 在整理方案的「洗版升级」里，评分规则选成本条（电影库和剧集库都用它）。
3. 评分规则要生效，整理方案里需开启**「洗版升级」**。
4. 建议同时开启**元数据提取（ffprobe）**：
   - 命名规则的 `{{probeSubtitle}}` 依赖它；
   - 评分规则里音轨、字幕、色深取不到值时，会按 `unknown_policy: ignore` 处理（双方跳过该维度，不判负，但也拿不到加分）。
5. **正式整理前先用少量文件试跑**，确认分类落点、命名结果、洗版判定都符合预期。

## 常见问题

**Q：4K 流媒体和 1080p 蓝光谁赢？**
要分情况。实测：`2160p WEB-DL SDR` 483.9 分 > `1080p 蓝光` 407.0 分，4K 仍占优；但 `1080p Remux+蓝光` 525.6 分 > `2160p WEB-DL SDR`，因为片源权重 18 让 Remux 反超。这正是「片源优先于分辨率虚标」的取向。

但洗版阈值是 80：`1080p 蓝光 → 2160p WEB-DL SDR` 虽然分数更高，净收益只有 +76.9，**不会触发洗版**。要真的换成 4K，通常得等到 4K 蓝光 HDR10（+195）或 4K 原盘（+461）。想彻底让 4K 通吃，把 `resolution` 提到 44、`source` 降到 12，并把阈值降到 40。

**Q：想让 4K 和 1080p 各留一份怎么办？**
给电影规则加 `version.dimensions: [resolution]`，两个分辨率各成槽位，各自组内比最优。

**Q：为什么必须留一版 ISO？**
因为 ISO 走独立槽位，不与非 ISO 竞争。不想要的话把 `version.enabled` 改成 `false`，ISO 会因容器分最低被正常洗掉。

**Q：改 `priority` 的档位顺序有用吗？**
有用，且比改 `weight` 更精准。`weight` 只调整维度占比，`priority` 的顺序决定「谁比谁好」，档位数还决定档位之间的间距。

## 已知限制

规则效果依赖 MediaTidy、TMDB 以及媒体文件自身元数据的完整性和准确性。以下情况可能造成偏差：

- TMDB 元数据缺失或错误（分类、命名都会受影响）
- 合拍片、跨国制作的归属判断
- 文件名无法识别片源或分辨率
- HDR / Dolby Vision 识别不完整
- 音轨、字幕轨的语言标记错误
- 不同母版、不同压制版本的实际画质差异（评分无法反映压制质量、降噪、调色等）

这些规则是**自动整理的依据**，不是对画质的绝对判断。评分高 ≠ 实际观感一定好。
